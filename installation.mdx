This guide covers everything needed to run NanoJev inference and reproduce the training pipeline: system prerequisites, creating a Python virtual environment, installing pinned dependencies, downloading model checkpoints and training data from HuggingFace, and validating the installation. By the end your environment will be ready to serve decisions, evaluate game controllers, or continue training from a hosted checkpoint.

## Prerequisites

Before installing NanoJev, ensure the following are available on your system:

| Requirement | Minimum | Notes |
|---|---|---|
| **Python** | 3.11+ | 3.14.4 was used in development |
| **NVIDIA CUDA GPU** | Required | A100 80 GB used for all benchmarks |
| **Git** | Any recent version | For cloning the repository |
| **Disk space** | ~10 GB | For model weights, dataset, and generated artifacts |

All inference and training scripts require a CUDA-capable GPU. The data generators and schema validation scripts use only the Python standard library and run without a GPU.

## Python dependencies

Clone the repository and create an isolated virtual environment:

```bash
git clone https://github.com/TianyuCodings/NanoJev.git
cd NanoJev
python3 -m venv .venv
source .venv/bin/activate
```

Install the pinned dependency set:

```bash
python -m pip install -r requirements-toy.txt
```

The following versions are pinned in `requirements-toy.txt`, recorded from the development environment (Python 3.14.4 / A100 80 GB):

| Package | Pinned version |
|---|---|
| `torch` | 2.14.0 |
| `transformers` | 5.17.0 |
| `safetensors` | 0.8.0 |
| `numpy` | 2.5.3 |

No API keys or external service accounts are required for the programmatic-supervision workflow.

## Model downloads

NanoJev publishes a root checkpoint and six task-specific variants in the [`C-Tianyu/NanoJev`](https://huggingface.co/C-Tianyu/NanoJev) repository. Choose the download that matches your intended use.

<Tabs>
  <Tab title="Maze Demo">
    Downloads the `local_atomic_seed17` variant — the checkpoint used for the 50×50 maze showcase with four parallel local safety judgments.

    ```python
    from pathlib import Path
    from huggingface_hub import snapshot_download

    variant = "local_atomic_seed17"  # Select "games_gold_seed17" for Snake.
    snapshot = snapshot_download(
        repo_id="C-Tianyu/NanoJev",
        allow_patterns=[f"variants/{variant}/*"],
    )
    checkpoint_dir = Path(snapshot) / "variants" / variant
    ```

    Pass `checkpoint_dir` to `serve_decisions.py` or any evaluation script to use this checkpoint directly.
  </Tab>
  <Tab title="Snake Demo">
    Downloads the `games_gold_seed17` variant — the checkpoint used for the 12×12 Snake showcase with dynamic action choice candidates.

    ```python
    from pathlib import Path
    from huggingface_hub import snapshot_download

    variant = "games_gold_seed17"  # Select "local_atomic_seed17" for Maze.
    snapshot = snapshot_download(
        repo_id="C-Tianyu/NanoJev",
        allow_patterns=[f"variants/{variant}/*"],
    )
    checkpoint_dir = Path(snapshot) / "variants" / variant
    ```

    Pass `checkpoint_dir` to `serve_decisions.py` or any evaluation script to use this checkpoint directly.
  </Tab>
  <Tab title="Base Checkpoint">
    Downloads the root checkpoint — the initialization model and the earlier 40-map navigation baseline. Also downloads the complete dataset into an explicit local directory.

    ```python
    from huggingface_hub import snapshot_download

    snapshot_download(
        repo_id="C-Tianyu/NanoJev",
        local_dir="checkpoints/NanoJev",
        allow_patterns=[
            "best.safetensors",
            "config.json",
            "tokenizer/*",
            "backbone_config/*",
        ],
    )
    snapshot_download(
        repo_id="C-Tianyu/NanoJev-Data",
        repo_type="dataset",
        local_dir="data/NanoJev",
    )
    ```

    The model patterns select the final root checkpoint. After downloading, serve it with:

    ```bash
    CUDA_VISIBLE_DEVICES=0 python scripts/serve_decisions.py \
      --checkpoint-dir checkpoints/NanoJev \
      --web-root web --host 127.0.0.1 --port 8765 --precision bf16
    ```
  </Tab>
</Tabs>

### Checkpoint variants

The full set of available variants in the [`C-Tianyu/NanoJev`](https://huggingface.co/C-Tianyu/NanoJev/tree/main/variants) repository:

| Checkpoint (`variants/`) | Purpose | Training data (`games_v4/data/`) |
|---|---|---|
| `local_atomic_seed17` | 50×50 maze showcase; four local safety judgments | `local_maze_v1/` |
| `games_gold_seed17` | Snake showcase; dynamic action choices | `scaled_games_v4b/policy/` |
| `games_api_seed17` | Full-map game-question comparison | `scaled_games_labeled_v4/` |
| `events_ce_seed17` | Observed-event CE control | `scaled_games_v4b/events/` |
| `events_brier_seed17` | Observed-event Brier control | `scaled_games_v4b/events/` |
| `events_paired_seed17` | RLCD-inspired paired proper-reward experiment | `scaled_games_v4b/events/` |

Each variant directory includes complete model weights, tokenizer, backbone configuration, and the recorded training configuration and summary.

## Dataset download

The [`C-Tianyu/NanoJev-Data`](https://huggingface.co/datasets/C-Tianyu/NanoJev-Data) dataset contains the original training stages, the games data package, frozen evaluation inputs, and all six Snake controller recordings.

```python
from huggingface_hub import snapshot_download

snapshot_download(
    repo_id="C-Tianyu/NanoJev-Data",
    repo_type="dataset",
    local_dir="data/NanoJev",
)
```

To download only the game data package:

```python
from huggingface_hub import snapshot_download

snapshot_download(
    repo_id="C-Tianyu/NanoJev-Data",
    repo_type="dataset",
    local_dir="data/NanoJev",
    allow_patterns=["games_v4/*"],
)
```

The dataset provides `stage1/all.jsonl` and `stage2/all.jsonl`, each with existing split assignments (`train`, `dev`, `calibration`, `test`, `ood`). Both files use the same training record interface as locally generated data.

## Verify the installation

After downloading the dataset, confirm that the training records are valid before loading any model:

```bash
python scripts/train_pipeline_decisions.py \
  --input data/NanoJev/stage1/all.jsonl --validate-only

python scripts/train_pipeline_decisions.py \
  --input data/NanoJev/stage2/all.jsonl --validate-only
```

`--validate-only` checks state and source-group separation, question field completeness, probability constraints, and split assignments without loading the model or touching a GPU. You can also pass a directory containing standard split files instead of a merged JSONL.

## Pre-training setup

If you intend to train a new NanoJev model from scratch rather than serving a hosted checkpoint, cache the required Qwen3-0.6B base revision before running the training scripts:

```bash
python - <<'PY'
from huggingface_hub import snapshot_download
snapshot_download(
    repo_id="Qwen/Qwen3-0.6B",
    revision="c1899de289a04d12100db370d81485cdf75e47ca",
)
PY
```

All training commands in the pipeline reference this exact revision. Pass `--model Qwen/Qwen3-0.6B --revision c1899de289a04d12100db370d81485cdf75e47ca` to `train_pipeline_decisions.py` to reproduce the published checkpoints.

<Warning>
  Changing the Qwen3-0.6B revision will break compatibility with existing checkpoints. The decision heads are initialized and trained against a specific backbone parameter layout. Always use revision `c1899de289a04d12100db370d81485cdf75e47ca` when continuing from a hosted checkpoint or reproducing published results.
</Warning>
